# AI System Register Template

## Purpose

This template helps organisations maintain a central register of AI systems, AI-enabled tools, models, and third-party AI services.

An AI system register is a foundational AI governance control. It provides visibility over where AI is being used, who owns it, what data is involved, what risks exist, and whether the system has been reviewed and approved.

---

## AI System Register

| Field | Description | Example |
|---|---|---|
| AI System Name | Name of the AI system, model, tool, or AI-enabled service. | Customer Complaint Classification Tool |
| Business Area | Department or function using the AI system. | Customer Operations |
| System Owner | Person accountable for the system. | Head of Customer Operations |
| Technical Owner | Person/team responsible for technical support or configuration. | Data Science Team |
| Risk Owner | Person accountable for managing the risk. | Operational Risk Manager |
| Purpose / Use Case | What the AI system is used for. | Categorises customer complaints by topic and urgency. |
| AI System Type | Type of AI capability. | Classification model |
| Deployment Status | Current lifecycle stage. | Proposed / Pilot / Production / Retired |
| Data Used | Type of data processed by the AI system. | Customer complaint text, case ID, product category |
| Data Sensitivity | Classification of data used. | Internal / Confidential / Personal Data / Sensitive Data |
| Third-Party Vendor | Whether an external provider is involved. | Yes / No |
| Vendor Name | Name of AI provider or supplier. | Example AI Provider Ltd |
| Risk Classification | Overall AI risk rating. | Low / Medium / High |
| Human Oversight Required | Whether human review is required before decisions are made. | Yes |
| Regulatory Relevance | Relevant legal, regulatory, or compliance obligations. | GDPR, FCA expectations, EU AI Act |
| Security Review Completed | Whether cyber/security review has been completed. | Yes / No |
| Privacy Review Completed | Whether DPIA or privacy review has been completed. | Yes / No |
| Approval Status | Governance approval status. | Pending / Approved / Approved with Conditions / Rejected |
| Review Frequency | How often the system should be reviewed. | Quarterly |
| Last Review Date | Most recent governance or control review. | DD/MM/YYYY |
| Next Review Date | Planned next review. | DD/MM/YYYY |
| Key Risks | Summary of material risks. | Bias, inaccurate classification, personal data exposure |
| Key Controls | Summary of controls in place. | Access control, human review, monitoring, vendor assurance |
| Notes | Additional comments. | Requires annual vendor assurance review. |

## Practitioner Notes

The AI system register should be reviewed regularly and updated when:

- A new AI system is introduced.
- A new data source is added.
- A vendor or third-party provider changes.
- The AI system moves from pilot to production.
- The risk classification changes.
- A material incident, complaint, or control failure occurs.
- Regulatory or governance requirements change.
