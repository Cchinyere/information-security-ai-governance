# AI Security Control Attestation Template

## Purpose

This template can be used by control owners, system owners, risk owners, compliance teams, and internal audit teams to confirm whether AI security controls are implemented, evidenced, reviewed, and operating effectively.

The attestation should be completed for AI systems that are in development, pilot, production, or material use within the organisation.

## Detailed Control Review

### 1. Data Governance and Training Data Security

| Question | Response |
|---|---|
| Has the data used by the AI system been identified and classified? |  |
| Has the lawful basis or approved business basis for data use been documented? |  |
| Has sensitive, confidential, or regulated data been approved for use? |  |
| Are data quality, integrity, and retention requirements defined? |  |
| Is there evidence of privacy, security, or data protection review? |  |

**Evidence Examples**

- Data inventory
- Data classification record
- DPIA or privacy assessment
- Data flow diagram
- Data retention schedule
- Data usage approval

---

### 2. Model Security and Supply Chain

| Question | Response |
|---|---|
| Has the model source, vendor, or development process been documented? |  |
| Are model changes subject to review, approval, and version control? |  |
| Has the AI supply chain been assessed for security and dependency risk? |  |
| Are testing, validation, and release controls in place? |  |
| Are model limitations and assumptions documented? |  |

**Evidence Examples**

- Model documentation
- Change approval record
- Vendor assurance report
- Security assessment
- Model validation report
- Version control record

---

### 3. Prompt and Input Security

| Question | Response |
|---|---|
| Are controls in place to prevent prompt injection or malicious input? |  |
| Are users trained on safe and approved AI input practices? |  |
| Are sensitive data inputs restricted or monitored? |  |
| Are input validation or filtering controls applied where appropriate? |  |
| Are misuse scenarios considered during testing? |  |

**Evidence Examples**

- Prompt security guidelines
- User training records
- Input validation rules
- Testing results
- Acceptable use policy
- Monitoring logs

---

### 4. Output Security and Reliability

| Question | Response |
|---|---|
| Are AI-generated outputs reviewed before use in sensitive or regulated processes? |  |
| Are accuracy, reliability, and quality checks defined? |  |
| Are users warned about limitations, hallucinations, or uncertainty? |  |
| Is human oversight required for high-impact decisions? |  |
| Are output errors, complaints, or quality issues tracked? |  |

**Evidence Examples**

- Output review procedure
- Quality assurance records
- Human review logs
- Decision approval records
- Error tracking reports
- Escalation procedure

---

### 5. Access Control and Identity

| Question | Response |
|---|---|
| Is access to the AI system based on role and business need? |  |
| Are privileged users identified and reviewed periodically? |  |
| Is multi-factor authentication enforced where appropriate? |  |
| Are joiner, mover, and leaver processes applied? |  |
| Are access logs reviewed for unusual or unauthorised activity? |  |

**Evidence Examples**

- Access control matrix
- User access review
- Privileged access review
- Authentication configuration
- Joiner, mover, leaver records
- Access logs

### 7. Vendor and Third-Party AI Risk
